# 个人与企业空间界面和删除导航执行计划

本计划将 2026 年 10 月 2 日的五项界面讨论和删除后导航问题合并为一个 Android 实施范围：
主动删除当前会话后回到原助手的新草稿，减少空间首页重复动作，提前展示企业配置版本，
补齐公开配置详情，并统一卡片刷新触发及未知状态的显示规则。

本文保留实施契约，并在文末记录本次实现与验收证据。制定计划时工作树干净，核对基线为
`1263531b8`；本次实现基于该提交，实施前已重新检查工作树和相关调用链。
现有 HTML 演示只用于说明内容及交互；其中企业名、版本、地址和时间均为示例，
脚本检查不能替代 Compose 和设备验收。

## 范围与完成标准

| 用户问题 | 实施结果 | 完成标准 |
| --- | --- | --- |
| 删除企业助手最后一个对话后出现会话不可用 | 个人和企业共用可靠的删除后导航；正常删除不经过错误页 | 原助手仍可用时进入同域同助手 Draft，不要求再次选择助手或 Starter |
| 首页第一张卡片重复展示聊天历史 | 卡片移除历史按钮；右上角菜单保留全空间历史入口 | 企业菜单标为全部聊天历史，抽屉继续按当前助手和文件夹筛选 |
| 企业配置版本难以核对，详情不完整 | 详情首屏显示当前生效版本；补发布身份和公开资源事实 | 显示已提交版本，完整核对信息可复制，定义和本域使用选择分开 |
| 卡片刷新与远程工作区显示不一致 | 首次未知不显示工作区；按真实开通状态决定显示；统一刷新触发 | 未提供和未开通不占卡片位置，查询失败不解释成未开通，旧授权不复活 |
| 开始对话过于突出 | 两种空间标题右侧使用一致图标按钮 | 标题有弹性宽度，图标右对齐，至少 48dp 触摸区，具备提示和无障碍名称 |

仅修改 Android 仓库中相关 `app` 实现、必要测试、五语言资源及所属参考文档。
Core、Admin、Relay、Agent Space 和 Portal 仅作为只读合同或联调依赖。
不改版本号、changelog、发布配置、远程文件写协议、会话数据格式及备份格式。
本轮首先利用已经保存的数据，发布时间持久化作为单独后续项，不加入本次数据迁移。

## 实施前基线事实与验证问题

| 入口或组件 | 已核对事实 | 实施前需要确认 |
| --- | --- | --- |

| `EnterprisePage` | 企业卡片正文含历史、工作台、切换和开始对话；个人入口在标题右侧 | 两域按钮位置统一，动作语义保持原入口约定 |
| `EnterpriseConfigurationDetailsUiModel` | 有 generation 和最近同步时间；版本展示在详情底部 | 发布身份的授权读取及版本一致性；不能分别读取后拼接不同提交版本 |
| `RemoteWorkspaceService` | 刷新开始发布 CHECKING；状态查询与打开共用原服务；已按原身份合并在途查询 | 分开开通事实、刷新阶段与当前文件可用性，保留原撤销屏障 |
| 远程摘要投影 | 无 agentSpaceId 且服务非 ENABLED 时隐藏；服务 ENABLED 但用户未开通仍可显示 | 用户未开通时也隐藏；有已开通资源但临时不可用时保留诊断 |
| `EnterpriseVM` | 动态刷新时不带旧内容；前台恢复显式刷新预算和工作区；配置同步成功刷新动态 | 前台动态刷新、重复触发合并、局部错误归属、停订阅后的行为 |

个人与企业共用删除和新建路径，个人目前表现顺畅不代表这条链没有竞态。

## 删除后的会话和导航协议

### 用户行为

| 操作 | 成功后行为 |
| --- | --- |
| 抽屉删除当前会话，无论是不是最后一个 | 同空间、同助手的新 Draft；不打开 Starter 选择，不自动发送 |
| 抽屉删除其他会话 | 当前聊天、输入和附件保持不变 |
| 历史页删除单条或批量删除 | 停留历史页，保持原删除反馈；返回栈中匹配的已删除聊天入口不再被打开 |
| 历史页撤销单条删除 | 原树及文件引用按现有 RestoreToken 恢复；不覆盖新草稿、不夺取已开始的聊天 |
| 冷启动最近引用已失效 | 经合法启动入口选取本域新聊天；企业无有效助手时进入选择入口 |
| 外链、搜索、收藏或通知指向不存在的会话 | 保留不可用说明；不把任意历史 ID 自动转为新建 |
| 原助手撤销或不可用 | 明确说明原因并提供选择入口；不自动切到目录首项或空间默认助手 |
| 操作中切域、重新登录、离开原聊天 | 旧结果不能导航到新空间、清空新返回栈或取得新 Session 授权 |

删除后沿用的是被删除会话的 `assistantId`，不是重新读取全局选中助手。
新草稿不继承被删除会话的 Opening、自定义 System、历史消息、工作区目录、附件或生成任务。
原会话仍有生成时，继续等待既有 stop 和资源退出协议完成，再提交删除。
首条 `AppendUserMessage` 才持久化新草稿，不提前建立空会话或 Turn。

### 实现职责

1. 由 `ConversationApplicationService` 继续编排原类型化删除命令，保留原 Session、选择 revision 和会话目标。
   删除成功返回可识别本次提交的结果；删除提交与后续新建请求失败必须可区分。
   不建立新的删除服务、全局导航事件总线或第二套恢复状态机。
2. 抽屉只提交命令。执行与结果状态留在 `ChatVM` 的稳定生命周期，避免依赖抽屉的 composition 协程。
   在删除前捕获正在查看的会话和助手，记录本次是否需要接续导航；非当前会话不触发接续。
3. `ChatPage` 在 Loading、Missing、Failed 提前返回之前消费单次、可确认的导航结果。
   已知本次删除正在提交或接续时显示短暂交接状态，不能凭任意 Missing 自动创建聊天。
   消费时确认原聊天入口仍匹配且原选择仍有效，导航完成后确认消费，旋转不能重复创建。
4. 历史页在 `HistoryVM` 中执行单条、批量和撤销命令。删除成功后，经现有 `Navigator`
   增加一个确有消费者的定向入口，处理返回栈中与删除结果匹配的聊天目标，并停留历史页。
   匹配包含会话 ID、原 scope 和 Session；不得暴露任意编辑返回栈的通用接口给业务层。
   替换后的入口固定原助手；助手不可用时使用明确的选择入口。Undo 恢复数据不强制跳转。
5. `ConversationApplicationService.initialRequest` 在打开最近 ID 前读取 scoped 根 header 并验证存在及归属。
   缺失走合法启动路径；异常保留诊断，foreign scope 和子会话不被接纳。
   header 核对与真正打开之间的删除竞态需验证；只能在明确的启动接续上下文恢复，不能改变显式历史打开协议。
6. `SettingsStore` 在现有提交锁内提供按 scope 和 expected ID 条件清理最近引用的协议。
   删除后的清理不能抹掉另一聊天刚写入的最新引用，不改个人或其他企业主体的偏好。

Room 删除与 DataStore 最近引用清理是两个 owner 的提交，不能宣称为一个原子事务。
先确认会话删除提交，再清理匹配引用；进程在两步之间退出由启动存在性核验处理。
若偏好清理失败，删除事实仍成立，保留原异常和可行动反馈，不把已经删除报告为完全未执行，
不重放删除或撤销新聊天；即使旧指针仍在，下一次启动也不能直接打开失效会话。
取消仍向上传播，仅现有取得提交或资源所有权的片段允许必要的不可取消清理。

### 不可用与失败文案

Missing 使用“会话已删除或不存在”等准确说明，保留显式新聊天和空间入口；
确定不存在时去掉“重试以重新初始化”的误导动作。
读取失败继续提供重试、可展开和复制的原异常；授权变化说明原页面权限，不据此断言当前企业整体失效。
更新现有恢复 UI 测试，不删除它们对失败诊断和空间入口的保护。

个人选择下不展示企业工作区卡片，也不能发起要求企业当前选择的远程查询。
原有预算提醒、接入、退出和恢复内容继续按实际状态出现。

| 动作 | 位置和行为 |
| --- | --- |
| 开始对话 | 两域第一张卡片标题右侧，复用 `HugeIcons.MessageAdd01` 与现有 Tooltip |
| 企业开始对话 | 保留 `EnterpriseStarterPicker`，可选助手或任务入口；不自动发送 |
| 个人开始对话 | 保留原入口和启动偏好行为，本次只改变显示形式 |
| 全部聊天历史 | 企业页面右上角更多菜单，进入现有 HistoryPage；不另建历史列表 |
| 个人聊天历史 | 如保留菜单快捷入口，继续原个人历史范围，不改成所有个人助手 |
| 工作台和切域 | 保留第一张卡片现有动作与准入，不移入新业务流程 |
| 刷新状态 | 页面标题栏图标，仅查询工作区、动态和预算 |
| 同步配置 | 企业连接卡强调按钮，仍是显式配置同步命令；配置详情为次要动作 |
| 修改地址和退出 | 页面顶部更多菜单，退出位于末尾，保留现有确认和原身份约束 |
| 用量预算和本机数据 | 页面更多菜单继续保留原语义 |

标题使用弹性宽度和省略，图标右对齐，触摸区至少 48dp；不以缩小 IconButton 尺寸解决密度。
新聊天、刷新和更多均提供本地化 contentDescription，关键图标有长按提示。
按钮准入继续消费既有投影，配置待下发或实际不可用时保持原拒绝语义，不用视觉统一放宽授权。
窄屏、较大字体、平板和折叠屏详情返回层级均要验收。

## 配置版本与公开详情

### 版本显示和数据来源

连接卡显示“最近成功同步”；“当前生效版本”放在配置详情第一张卡供核对，避免首页重复。
`generation` 的用户名称改为“当前生效版本”，不使用容易误解的“配置代次”。
配置序号与快照格式版本分别标注；它们都不是 APK versionName。
“当前生效”明确指本机已应用配置，不暗示已知道服务端最新发布版本。

| 字段 | 来源与当前情况 | 本次处理 |
| --- | --- | --- |
| 配置序号 | 已提交 manifest 的 applied generation | 配置详情首屏 |
| 最近成功同步 | 现有 lastConfigurationSyncMillis | 首屏使用设备语言及时区，空值显示未记录 |
| 发布 ID | 已保存 EnterpriseExecution.Platform.releaseId | 发布与核对信息内可复制 |
| 配置 SHA-256 | 已保存 snapshotHash | 默认短展示或折叠，复制始终使用完整值 |
| 配置格式版本 | 已保存 snapshotSchemaVersion，可为历史 null | 单独展示，null 标为未记录，不反推为 4 或 5 |
| 平台来源 | 原 Session 连接与企业身份 | 沿用公开地址；必要的 deploymentId 可放核对信息 |
| 发布时间 | 下发 metadata 有，但 mapper 未保存在 Applied 中 | 本次不虚构、不借用 Feed 时间，不做持久化变更 |

在 `EnterpriseSessionController` 原授权读取边界形成同一 applied revision 的公开发布摘要，
再由 `EnterpriseApplicationService` 投影给详情。UI 不取得整个 execution、runtimePaths 或 credential。
不能分别读取 manifest 和另一 revision 的 execution 后拼接；迟到结果复验原 Session、选择与 applied revision。
现有 `readExecution` 包含运行兼容校验，实施时不得直接复用为会阻断只读诊断的入口；
必要时扩展原 Session 的只读投影语义，保持可执行准入和公开诊断读取职责清楚。
个人页只读查看已连接企业时沿用原授权，不要求伪装成已选企业，也不执行企业资源。

“复制核对信息”包含企业名称、配置序号、发布 ID、完整摘要、已知格式版本、同步时间和平台地址。
离线显示本机已应用版本及离线说明；同步失败保留旧版本并显示失败，不能把失败时间改成成功同步时间。
无 Applied 时显示配置待下发或现有兼容诊断，不展示虚假版本或空的资源详情。

### 资源内容和渐进披露

保留现有“默认配置、使用规则、企业资源”层次，标题下不堆所有参数。
只补充能核对下发内容或解释选择结果的公开字段；资源标识放详情中按需复制。
列表仍为轻量摘要，System、初始背景和记忆正文不复制进首页热路径。

| 类别 | 补充内容 | 展示与约束 |
| --- | --- | --- |
| Provider | 公开协议和资源标识 | 原详情轻量字段；不显示 upstream 地址、headers 或密钥 |
| 聊天模型 | 模型标识、输入输出类型、工具和推理能力、Provider | 只按真实公开定义显示；失效引用保留原因 |
| 图像资源 | 模型、公开协议；保留已有数量和尺寸限制 | 不把文本模型的 IMAGE 输入能力当作文生图 |
| 企业助手 | 默认模型、固定 MCP、System Prompt；相关公开定义 | 复用原助手只读详情，企业定义与本域用户模型选择明确区分 |
| Starter | 完整起始提示词、关联助手、开场格式与初始背景 | 复用原授权详情；大段正文折叠；v4 未提供 Opening 明确标注 |
| TTS | 公开协议、模型、音色、实际下发语速和音调等 | 未提供字段不补客户端虚构默认；长提示按需披露 |
| ASR | 协议、模型、语言和实际下发的识别参数 | 仅显示该协议适用字段；不以标题代替实际配置 |
| MCP | 资源标识、启用状态、认证管理归属 | 定义启用不等于实际连接成功，不决定远程文件入口 |
| Memory Seed | 保留已有数量摘要 | 不扩张当前正文读取资格；需要正文时仅复用已有授权入口 |
| Gateway | 当前实际存在的公开定义字段 | 沿用支持范围；不因 UI 详情预设未发布平台能力 |

若复用详情需要从快照转换资源身份，只在原 application/query 层形成 typed target；
不能把按索引生成的显示 key 当成稳定 definition ID 或读取授权。
同步导致资源撤销或身份变化时关闭旧详情目标，原有层级返回规则继续有效。

## 远程工作区显示规则

工作区的开通和文件资格来自 Core WorkspaceProjection，与本地 Workspace、MCP、模型、预算和 Applied 配置分开。
CONFIGURATION_PENDING 但有效 Session 允许文件查询及管理的现有协议继续保持。

| 状态 | 首页卡片 | 连接区域反馈 | 文件操作和聊天快捷入口 |
| --- | --- | --- | --- |
| 首次未知或第一次检查中 | 隐藏 | 整页刷新可表达正在查询，不单独放检查中卡片 | 不显示快捷入口 |
| 协议未提供或明确未开通 | 隐藏 | 无错误；显式刷新仍可发现后续升级或开通 | 不显示快捷入口 |
| 首次查询失败，是否开通未知 | 隐藏 | 局部服务查询失败、完整诊断和重试 | 不提供文件动作 |
| 已确认开通且文件可用 | 显示紧凑摘要 | 无额外提示 | 原身份仍有效且查询可信时提供入口 |
| 已确认开通后刷新中 | 保留原开通摘要，标刷新中 | 无全页错误 | 当前可用性待复验，快捷入口隐藏，已打开页不绕过原 service 校验 |
| 已确认开通后刷新失败 | 保留，标状态待确认 | 诊断归该资源，不冒充未开通 | 不以旧结果重新开放文件动作，可进入状态页重试 |
| 已开通资源正在连接或恢复 | 保留状态卡 | 状态页提供真实原因 | 暂不提供文件动作 |
| 已开通资源被禁用、正在删除或需要处理 | 保留真实状态和诊断 | 不丢失有用的故障信息 | 原 service 撤销资格及句柄 |
| 成功查询确认已删除或不存在 | 隐藏 | 无常驻空卡；必要操作结果留在原页面 | 撤销旧句柄和快捷入口 |
| 切域、退出、Session 或连接身份变化 | 立即移除旧卡片和摘要 | 新身份从未知开始 | 旧查询取消并排空，迟到结果丢弃 |

以当前成功投影的 agentSpaceId 和实际生命周期组合判断已开通，不能只用 serviceState=ENABLED。
无资源但准备开通的初始 CONNECTING 不构造已开通事实；有原资源的临时连接异常仍可显示状态。
serviceState 禁用且没有资源时隐藏；有已开通资源时显示不可用原因。
成功返回“未开通”可替换旧事实；网络失败不能替换为“未开通”。

在 `RemoteWorkspaceService` 内保留必要的成功 projection 和查询结果，统一生成摘要，
明确区分是否开通、刷新中、失败及当前文件资格。UI 不保留自己的 lastAvailable 副本。
现有请求合并、generation 核对、bindingRevision/agentSpaceId 比较、handle 撤销、取消等待继续保留。
若文件读取已失败，状态刷新成功不能顺带把尚未核实的 readError 当作已恢复。
不能以这一轮显示调整改变文件写入单次尝试、条件写入和未知结果核实协议。

## 卡片刷新与错误归属

### 触发和合并

| 触发 | 身份和配置 | 工作区 | 动态 | 预算 |
| --- | --- | --- | --- | --- |
| 页面进入或恢复前台 | 订阅原 owner，读取已发布状态 | 按当前合法目标查询 | 刷新 | 刷新 |
| Session、选择或连接变化 | 原 owner 发布 | 撤销旧目标，由原监听刷新新目标 | 取消旧查询后读取新目标 | 清空旧目标，刷新新目标 |
| 页面刷新状态 | 不触发配置同步 | 刷新 | 刷新 | 刷新 |
| 局部刷新或重试 | 原职责内执行 | 只刷新工作区 | 只刷新动态 | 只刷新预算 |
| 用户同步配置成功 | 提交成功后更新版本和资源 | 可通过原状态刷新入口统一检查，不依据配置推断文件资格 | 刷新 | 更新状态摘要 |
| 用户同步配置失败 | 保留原已应用版本和诊断 | 独立可用，不阻塞 | 独立刷新 | 独立刷新 |
| 运行用量变化 | 不影响 | 不触发 | 不触发 | 沿用现有用量通知和在途刷新 |

统一入口由现有 `EnterpriseVM` 编排独立查询，合并同目标在途请求；
不能同时由 LaunchedEffect、ON_RESUME 和原服务监听发出无意义的重复首轮查询。
工作区合并继续由原 service 负责，预算沿用现有合并逻辑，动态在现有 VM 中保留必要请求状态。
没有完整合法目标时不启动远程请求。个人页的企业只读内容只能使用该 query 已允许的原授权。
页面恢复仅刷新状态，不能顺带下发或应用企业配置。
不新增后台服务、持久化刷新队列、TTL 配置、定时器、通用查询框架或整页原子快照。

预算现有在途请求定时刷新按原范围保留，但仅页面活跃且目标仍有效时运行。
页面在后台、离开空间页或打开内嵌工作台时，核对实际展示状态，避免隐藏页面持续轮询。
从配置详情、文件页或工作台返回仍按一次前台触发规则检查状态。

### 显示和失败

同一身份刷新时，保留工作区及动态旧内容；动态有旧数据时注明刷新失败和重试，
成功返回空列表才隐藏动态卡片。首次动态查询可保留原加载反馈，不能构造有内容的通知卡。
预算保留已有 stale 语义，不以过期预算推断其他服务不可用。

工作区、动态和预算错误分别显示在原资源或连接区域，完整诊断仍用既有 DiagnosticDisclosure。
身份、同步、退出和本机恢复错误继续原归属；不把所有错误拼为持续占位的全页“企业失败”。
正常状态不新增多行时间和技术 ID；必要查询时间可放诊断，以说明旧值的证据范围。
整页刷新按钮表达查询中，不因一个服务失败阻塞其他查询或长期禁用所有动作。
取消不显示失败，目标变化不回放旧反馈，成功局部重试只清除对应资源的错误。
