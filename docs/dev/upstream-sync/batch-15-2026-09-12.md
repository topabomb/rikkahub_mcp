### P01：语音预取与重试不是同一交付

TtsController 只决定播放窗口；TtsPlaybackSession.synthesize 回到 SpeechApplicationService 的原 realm 准入。当前段和最多两段预取属于同一 playback owner；取消、暂停、替换和 cleanup 沿原协议。追加入口只补足当前位置后两段，worker 取下一段后推进窗口；删除 lastPrefetchedIndex，避免追加继续前推。无产品调用的 skipNext 及 SpeechPlayback 转发已物理删除，防止跳过队列却留下已合成缓存。System/OpenAI/Gemini/MiMo 共用此机制。

不把 retry 包到所有 session 外：企业 HTTP 明确不重放，428 必须结束原交互；个人 HTTP 失败也未证明没有合成/计费。P01 完成只代表预取有界，不代表支持自动重试。

### P06：窗口、页面样式与 PTY 分工

MeasixTheme 只提供取色和 CompositionLocal。WindowSystemBars 由 RouteActivity 的 AppRoutes 根据真正显示的路由设置；仅 recovery Ready 且顶部为 WorkspaceTerminal 时强制深色，否则使用根主题。SafeModeActivity 设置自己的窗口。导出树、嵌套终端主题不写 Window，不建立颜色恢复栈。

UI 创建终端视图，session、writer、终态和跨域退休仍归 WorkspaceTerminalRuntime。删除 ACTION_UP 监听后，单击键盘由 Termux ViewClient 原手势完成；长按选择和滚动结束不强制重开 IME。消费 Scaffold padding 后使用 imeAnimationTarget，不重复计算 inset。

### P08–P09：请求身份、origin 与冻结配置

会话头复用 TextGenerationParams.providerSessionId，不新建 session store。具体网络 URL 才能判断 host，不能以 Google Vertex 会忽略的 baseUrl 代替。该头归执行 owner，自定义同名头不覆盖原会话。其他 host 不新增 X-Session-ID；自动头由 request tag 标识，现有共享 HTTP client 装配 ProviderSessionHeaderInterceptor，在跨 host 重定向的网络发送边界移除自动头，保留用户自定义 header 语义。OpenRouter session_id body 仍归原 adapter。

Responses path 为 additive 默认字段，不可替换 origin、包含查询/fragment 或明文及编码穿越；baseUrl 已有路径前缀保留。START 捕获 path，凭据 lease 随后只取新 apiKey，不读新 path。旧备份缺字段仍为 `/responses`；不需要 Room migration，但须验证配置序列化保全。

### P11：统计容错不代表持久化修复

json_valid/数组检查在 json_each 参数内，成员检查在 json_extract 参数内，不能依赖 WHERE 求值顺序。不可统计文档/成员不参与统计；不修改 payload，不将损坏聚合恢复为 Ready。正常 root 消息数、Child usage、usage 完整性与 scope 保持原口径。结果是可解析记录的统计，不宣称数据已完整修复。

### P12–P15：复用既有能力

ask_user 不增加答案 DTO、执行记录或恢复状态；声明归工具纯校验，UI 编码回答后等待原提交结果。缩略图借用 ImageSource，不解裸 File 绕过准入。AGENTS 正文作为工具结果进入 Step 历史与 rolling compaction；固定指引不意味着自动加载，也不扩大工具权限。

### P16：补充要求——模拟器 PRoot 与真实 Linux 验收

本项由用户追加，不改变 67 个上游提交的分类统计。已确认默认 Rootfs URL 固定 arm64，而 API 37 模拟器原生 ABI 是 x86_64；设备同时报告 arm64 原生桥支持，不能按 `SUPPORTED_ABIS` 是否含 arm64 判断应用实际 ABI。现有 PTY 测试启动 `/system/bin/sh`，不代表 Linux Rootfs 已验收。

实施顺序与责任：

1. `workspace/RootfsCompatibility` 以打包 PRoot ELF machine 为唯一 ABI 事实，选择同版本 Ubuntu 24.04.3 的 arm64/amd64 URL；经 Installer → Repository → QueryService → VM 给 UI，不在页面按模拟器品牌判断。
2. Installer 在 staging 校验 `/usr/bin/env`、`/bin/bash` 的 ELF、动态解释器及其架构，guest 绝对链接仍在 guest 根解析；校验及 patch 成功后才替换目录。错误包不先删除原有效 Rootfs。
3. 启动完整性检查将既存不兼容 READY 根及所有中断的 INSTALLING 状态收口 BROKEN；旧目录即使兼容也不能证明安装已发布，保留文件并允许重试，避免界面永久安装中。命令与 PTY 启动共用兼容校验。数据结构、arm64 镜像版本、`ProotLaunchSpec` 参数和 seccomp 策略不变，不增加兼容开关或自动重试。
4. 终端零 tab 使用已有退出文案，PREPARING 才表示创建中；非主动关闭的异常退出发布原 typed failure，正常退出和主动终止不误报。
5. JVM 覆盖两 ABI、损坏 ELF/解释器、guest 链接、取消、错包保全和启动完整性。`WorkspaceProotAndroidTest` 是显式 Rootfs fixture 的设备验收，传 `prootRootfsUrl` 后实际安装、运行生产 Shell、文件操作、长输出、超时/取消和双 PTY；无 fixture 的普通运行明确跳过，不能计作 PRoot 通过。
6. 实际匹配 amd64 首轮运行得到 libc `ELF load command address/offset not page-aligned`，退出 127；`getconf PAGESIZE` 和 AVD image 均证实为 16 KB 环境。新增 guest LOAD alignment/同余准入，实际页大小读取失败不猜测 4 KB；安装错误 UI 展示底层诊断。既有 16 KB AVD 验证拒绝并保全原目录，独立 API 36 / 4 KB AVD 验证真实运行。规则不更改 PRoot 参数或真机配置，也不声称静态入口校验覆盖所有动态依赖。
7. 4 KB 环境已运行 Linux 文件操作与长输出，但取消测试暴露 Android `Process.destroyForcibly()` 实际发送 SIGTERM、固定 PRoot 忽略该信号的问题。采用固定 PRoot 源码补丁：启动时阻塞 TERM/QUIT，guest fork 分支恢复原 mask，parent 登记 tracee 并安装 handler 后恢复 mask；TERM/QUIT 均由原 event loop 杀死并收回 tracee。双 ABI 重建并更新可审计构建来源；命令仍归 ProcessBuilder/readResult，PTY 保留 TerminalRuntime 并同样发 TERM，不添加 shell supervisor、PID 反射或设备分支。
8. 实际 Debug app Main 的 SigBlk 为 `0000000080001204`：ART 屏蔽 QUIT 而未屏蔽 TERM。因此 PTY 与 ProcessBuilder 统一使用 TERM，保留通用 JNI 的原继承协议；不依赖被继承阻塞的 QUIT。
9. 实际设备断言包含超时耗时、取消后 guest PID 消失、启动阶段取消、独立 stdin/stdout/stderr，以及关闭第一个 PTY 后其后台进程消失、第二个仍存活，关闭工作区后全部回收。计时标记与 UI tab 状态不能代替进程退出证据。

验收边界（2026-09-12 用户确认）：用户当前不方便连接真机，明确真机验证不应成为本次任务阻碍。本批以已经完成的双 ABI 构建/静态契约、完整自动门禁与实际 x86_64 Linux/PTY 模拟器验证交付；不将未执行的 arm64 运行描述为通过，也不改变第 13/14 批独立的历史验收记录。

以后有设备时可补充：在临时工作区安装默认 arm64 Rootfs；验证文件操作、stdin/stdout/stderr 与长输出；开启两个终端，分别验证关闭/取消后子进程回收且另一终端不受影响；验证现有工作区升级后可用及个人/企业切换时终端访问撤销。若有不同页大小设备，再补对应兼容准入。普通手机界面操作能覆盖基本使用，进程回收与启动/fork 取消竞态仍需设备 instrumentation；这份补测清单不要求用户现在执行。

资料与实验：

- [Ubuntu 官方镜像目录](https://cdimage.ubuntu.com/ubuntu-base/releases/24.04/release/)仍提供本项目使用的 24.04.3 双 ABI，故无需顺带升级发行版；本次 amd64 文件已对官方 SHA256SUMS 核验：`6bc2cde3930ad088b3bb46fa45279e96d25bc3810f209850ecbe4722711874f9`。
- [PRoot 官方手册](https://github.com/termux/proot/blob/v5.1.107.92/doc/proot/manual.txt)区分 ptrace 路径虚拟化与 QEMU 跨架构执行；本项目没有 QEMU，PRoot 本身不能把 ARM 指令转换成 x86。
- [Termux PRoot-Distro 官方说明](https://github.com/termux/proot-distro/blob/master/README.md)同样区分原生架构与显式 QEMU 跨架构执行。不能从某个内核的 `PROOT_NO_SECCOMP` workaround 推导所有模拟器都应禁用 seccomp。
- [Android 官方页大小指南](https://developer.android.com/guide/practices/page-sizes)要求核对 ELF LOAD 对齐与运行页大小；[官方实现说明](https://android-developers.googleblog.com/2024/08/adding-16-kb-page-size-to-android.html)说明 x86_64 16 KB AVD 会对应用施加 16 KB 对齐要求。本次核对原 arm64 镜像 env/bash/libc/ld 均为 64 KB 对齐，amd64 均为 4 KB；不混用两种环境的结论。
- [Android libcore 原生实现](https://android.googlesource.com/platform/libcore/+/837b789147d8f67538be3cfac95aea1343eaf36d/ojluni/src/main/native/UNIXProcess_md.c)的 destroy 发送 SIGTERM；[固定 PRoot event loop](https://github.com/termux/proot/blob/v5.1.107.92/src/tracee/event.c)将其忽略，而 SIGQUIT 进入 tracee 清理。修复启动信号窗口，避免只改变终止信号后留下 fork 与 handler 之间的竞态。
- 实际 RouteActivity 已完成工作区浅色 → 终端深色 → 返回浅色的系统栏观察；终端退出后旧 UI 持续显示 loading 的问题由此发现。真实 Rootfs/PTY 定向设备验收已通过，具体结果见下方设备证据。
