suspend fun callTool(serverId: Uuid, toolName: String, args: JsonObject): List<UIMessagePart> {
    val entry = clients.entries.find { it.key.id == serverId }
    var client = entry?.value
        ?: return listOf(UIMessagePart.Text("Failed to execute tool, because no such mcp client for the tool"))
    var config = entry.key

    // 调用前确保 OAuth 令牌新鲜
    val freshConfig = ensureFreshToken(config)

        addClient(freshConfig)
        val newEntry = clients.entries.find { it.key.id == serverId }

### 本地 MCP 实现与上游对比

本地 MCP 实现在上游 OAuth 基础上做了以下增强（详见 `docs/dev/mcp-lifecycle-analysis.md` 第十四章）：

| 维度 | 上游 | 本地 | 优势 |
|------|------|------|------|
| clients 类型 | `MutableMap<McpServerConfig, Client>` | `ConcurrentHashMap<Uuid, Client>` | 线程安全，sync 不改变 key |
| 并发控制 | 无锁 | per-server `Mutex` | 序列化所有操作，消除竞态 |
| 重连策略 | 5 次指数退避 → Error | 5 次指数退避 → Dormant(60s×30) → Error | 30 分钟兜底窗口 |
| 网络感知 | 无 | `NetworkMonitor` onAvailable → syncAll | WiFi↔蜂窝切换快速恢复 |
| 前台恢复 | 无 | `ProcessLifecycleOwner.onStart` → syncAll | OS 后台静默断开恢复 |
| 工具通知 | 无 | `tools/list_changed` 通知 → 自动 sync | 服务器工具变更自动感知 |
| callTool 错误分级 | 简单 Error | 超时/取消/授权/连接/其他 五级 | 精确恢复策略 |
| OAuth Job 管理 | 无特殊处理 | `authorizeInternal` 移除自身 Job 防 `cancelAllJobs` 自杀 | 授权流程不被中断 |
| `clearAuthorization` | 简单清除 | 保留配置 + 立即断开 + 设为 `NeedsAuthorization` | 避免清除后连接仍可用 |
| `createAndConnect` 异常处理 | `runCatching` | `try-catch` 确保 `closeClient` | 防止坏连接残留 |
| OAuth 错误解析 | 仅解析成功响应 | `executeRaw` 支持 400/401 错误体 | 正确显示授权失败原因 |
