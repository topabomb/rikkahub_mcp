# Android 自主通知接收后续设计

> 未实施。原研究日期为 2026-09-18，代码基线 `5de1b084`；详细研究过程保留在 Git 历史。
> 本文只保存目标、候选方案和验收边界，不代表当前服务端合同、Android 支持范围或实测可靠性。

## 目标与方案选择

在用户明确启用、运行与网络条件允许时接收业务提醒；中断后在保留期内补收，重复传输不重复入箱。
候选方案为独立前台服务、单条 OkHttp WSS 连接、服务端顺序持久消息流、Room 收件箱与游标、系统通知。
`specialUse` 的适用性、后台启动方式与发行渠道要求须在实施前重新核验，并先做目标设备的纵向验证。

首版不增加推送插件框架、独立进程或新模块，也不把聊天生成服务、MCP 连接或周期定时任务改成通知接收器。
不承诺强行停止、通知被禁用或系统禁止后台运行时仍实时提醒；接收、持久化、系统提交与用户已读分别表达。
电池设置、国内 ROM 和公网可达性都需要独立实测，不以模拟器或短时连接成功代替。

## 身份、连接与写入责任

- 一个接收绑定固定安装实例、服务端与不可变主体；使用专用接收凭据，企业消息仍要求原 Session 的有效访问资格。
- 独立网络 client 不继承模型认证与日志拦截器；使用正常 TLS 校验，凭据不放 URL，关闭鉴权请求的自动重定向。
- 单一 Controller 拥有连接代际、有限队列、退避和取消；旧连接回调、旧主体或已撤销 Session 无权入库及展示。
- 收件箱 owner 在同一 Room 事务中幂等写入消息并推进最高连续游标；事务成功后才 ACK。磁盘、迁移或授权失败不确认成功。
- 开关只保存一份；在线和重试是内存投影。启动先等待原应用恢复门禁，恢复链不能反向等待通知网络连接。
- 退出先撤销绑定，再关闭并等待连接、处理任务和通知清理；不在包含本任务的退出屏障里等待自身。

## 待定义的服务端合同

服务端应为每个 receiver 提供独立的持久顺序流，凭据可撤销，发布权限与接收权限分开。
业务终态与通知登记须明确事务边界；跨库场景需要可恢复交接，不能由一次无持久化 HTTP 调用承诺原子一致。

协议至少明确版本、stream 身份、事件幂等键、序号、资源引用、提醒有效期、resume/ACK、心跳与有限未确认窗口。
序号不直接当作跨并发事务的提交顺序；回放与直播均从持久记录读取，不能在切换时漏掉新消息。
客户端从自己的持久游标续传，服务端 ACK 不能覆盖本地事实或立即删除补发记录。

流重置、历史缺口、凭据撤销、版本不兼容和非法载荷必须有可行动诊断；不能跳到最新游标后宣称完整。
未知业务 kind 可保存有界字段并作通用展示，不能执行任意下发参数。具体端点、字段、保留期与限额在真实消费者确定后冻结。

## 系统展示、导航与备份

Room 与系统通知无法构成同一事务，采用稳定事件 tag 与待展示记录修复；系统提交成功不表示用户已看到。
崩溃窗口可能导致再次提交，不承诺严格一次展示。权限或频道关闭时仍保存消息并标记抑制，后来授权不重响全部旧记录。

通知打开请求经 `RouteActivity` 等待导航与恢复就绪，再按本地记录的原主体授权。
远程任务或会话 ID 不能直接当作本地 Conversation UUID；缺少验证映射时先进入通知详情，不自动切域或建会话。

接收凭据、设备身份和游标不进入可迁移备份。个人备份恢复保留同机最新接收状态，不回退游标；
新机或重装重新签发绑定。新增 Room 表须基于实施时的实际 schema 提供迁移、同构校验与数据保全测试。

## 实施与验收

1. 先验证真实 Service、WSS 和系统通知在目标设备熄屏及后台条件下的运行前提，再冻结产品支持范围。
2. 实现消息/游标事务、补发和展示修复，覆盖提交前后崩溃、ACK 丢失、重复/冲突事件及回放边界。
3. 接入原 Session 退出、启动恢复、冷/热通知导航、备份合并与诊断，验证撤权、旧回调、磁盘失败和取消实际退出。
4. 在拟支持的 AOSP 与国内 ROM 上进行长时熄屏、电池设置、网络切换、进程回收、系统停止、升级及通知权限测试。
   自动门禁、模拟器与真实服务分别记录，未实测的延迟和耗电不写为产品保证。
